# Fluxgate — панель управления HAProxy

Панель для маршрутизации по TLS SNI, учёта трафика серверов, квот и общих ограничений скорости. Поддерживает HTTP/1.1 и WebSocket.

## Установка одной командой на чистый Ubuntu/Debian

```bash
curl -fsSL https://raw.githubusercontent.com/bekjonbegmatov/FluxGate/main/install.sh -o /tmp/fluxgate-install.sh && sudo bash /tmp/fluxgate-install.sh
```

Скрипт установит Docker Engine и Compose, скачает проект, создаст случайные секреты, запустит контейнеры и напечатает готовый HTTP URL и токен входа. По умолчанию основной домен `cubeland.top`; для другого домена задайте `sudo FLUXGATE_DOMAIN=example.com bash /tmp/fluxgate-install.sh`. Откройте TCP 443 и 9389 в firewall хостинга. Повторный запуск сохраняет секреты и данные. [Подробная эксплуатация](docs/OPERATIONS.md).

## Обновление работающей Docker-установки одной командой

```bash
curl -fsSL https://raw.githubusercontent.com/bekjonbegmatov/FluxGate/main/update.sh -o /tmp/fluxgate-update.sh && sudo bash /tmp/fluxgate-update.sh
```

Обновлятор собирает новые образы при работающем прокси, скачивает и проверяет backup, сохраняет `.env` и прежние образы в `/var/backups/fluxgate/<дата>`. После переключения проверяет готовность, вход в API и полный TLS/SNI-путь через 443. При неудаче возвращает прежние образы с тем же томом данных. Во время переключения будет короткий перерыв: текущим соединениям потребуется переподключиться. Код обновляется только fast-forward; локальные изменения не перезаписываются.

Обновить **и задать потолок 100 000 одновременных соединений** (можно указать 40000, 50000 или 80000):

```bash
curl -fsSL https://raw.githubusercontent.com/bekjonbegmatov/FluxGate/main/update.sh -o /tmp/fluxgate-update.sh && sudo bash /tmp/fluxgate-update.sh --max-connections 100000
```

Прежняя `.env` сохраняется **до** изменения лимита; при неудаче возвращается вместе с прежними образами. Данные остаются в существующем томе — база, сертификаты, история, токены и платежи не удаляются и не заменяются устаревшим снимком. Backup нужен для отдельного восстановления. Без аргумента обновлятор сохраняет настроенный лимит; по умолчанию он остаётся 10000. Число за сутки — не одновременное количество: 100000 в сутки в среднем около 1,16 нового соединения/с.

100 000 — поддерживаемая настройка, **не гарантия мощности VPS**. Столько одновременно активных TLS/WS-соединений требует отдельной проверки CPU, RAM, FD и upstream. Один исходящий IP → один IP:порт upstream ограничен доступными TCP-портами; для 100k к одному сервису нужны несколько реальных upstream endpoints или корректно настроенные дополнительные исходящие IP. Просто несколько доменов, указывающих на тот же IP:порт, этот предел не снимают. В Docker диапазон исходящих портов расширен до 10000–65535 только внутри сетевого namespace контейнеров. Существующие соединения при достижении публичного лимита не обрываются; новые ждут в ограниченной очереди и могут получить timeout. После graceful reload старый worker дренирует свои соединения дополнительно к лимиту нового, поэтому нужен запас ресурсов. Relay дополнительно ограничивает допуск в Go суммарно по всем поколениям, отклоняя только новые подключения сверх лимита.

По умолчанию checkout находится в `/opt/fluxgate`, Compose-проект — `fluxgate`. Для другой папки: `sudo FLUXGATE_DIR=/ваша/папка bash /tmp/fluxgate-update.sh`. Домены, маршруты, токены, сертификаты и платежи сохраняются. При нестандартных Compose override-файлах используйте ручное обновление из [инструкции эксплуатации](docs/OPERATIONS.md).

## Производительность и длительная работа

В **Настройки → Режим проксирования** можно выбрать глобально:

- **Через Go relay** (по умолчанию, в том числе после обновления): квоты и ограничения скорости работают.
- **Напрямую через HAProxy**: `клиент → HAProxy → конечный сервер`. Go не передаёт данные маршрутов. HTTPS, WebSocket, SNI/wildcard, мониторинг и пауза сохраняются. Отдельная настройка **«Применять квоты и скорость в direct»** включает мягкие квоты и общий HAProxy bandwidth limit маршрута. По умолчанию она выключена, включая обновление старой direct-установки. При возврате на relay сохранённые квоты применяются к уже накопленному использованию.

Смена режима требует подтверждения и переподключения активных соединений. При direct bandwidth limit старые соединения маршрута также завершаются после reload: иначе разные поколения HAProxy имели бы независимые бюджеты скорости. Остальные туннели сохраняют graceful reload. Выбор хранится в SQLite и переносится в backup. Прямой режим требует HAProxy 3.2 с доступным Runtime API (в Docker уже включён). Fallback-страницу в обоих режимах обслуживает traffic agent.

**Direct-квота не является строгой границей байтов.** После превышения дневной или месячной квоты агент переводит backend в maintenance и закрывает активные сессии, включая старые workers; новые запросы получают 503. Пополнение и смена периода открывают маршрут снова. Возможен перерасход до обновления/опроса счётчиков, обычно несколько секунд; на гигабитном канале это могут быть сотни мегабайт. При зависании агента или всей панели отдельный watchdog в контейнере HAProxy закрывает маршруты с квотами; без доступного Runtime API такая защита не гарантируется. Для строгой квоты выбирайте relay.

В прямом режиме HAProxy обновляет счётчики длинных потоков примерно каждые 5 секунд (`contstats`), панель опрашивает их каждую секунду, скорость сглаживается за 10 секунд. Сохранение в SQLite пакетное, по умолчанию раз в 5 секунд. Учитываются HTTP/WS-байты HAProxy, **без TLS/TCP/IP**; в relay считаются TLS-байты. Исторические суммы из разных режимов поэтому не полностью сопоставимы. При обычном reload панель удерживает доступ к старому worker до сохранения последних счётчиков. После аварийного завершения HAProxy возможна потеря неснятого остатка; после перезапуска только панели — остатка старого worker, завершившегося до повторного опроса. Это эксплуатационная статистика, не биллинг с гарантией exactly-once при любых авариях.

Кнопка **«Перезапустить панель и HAProxy»** в настройках сохраняет счётчики и перезапускает веб-процесс, traffic agent и HAProxy после подтверждения. VPS не перезагружается, настройки/платежи/сертификаты остаются. Текущие соединения оборвутся. Бинарник теперь содержит supervisor; Docker/systemd остаются внешней страховкой. Кнопка не предоставляет панели Docker socket или shell-доступ.

Панель и обработчик трафика работают в разных процессах внутри прежнего контейнера `panel`. Веб-процесс читает графики/CSV через отдельный read-only пул SQLite (до 4 соединений); у агента один writer. Падение веб-процесса не перезапускает relay. Collector direct больше не ждёт SQL/stateMu: контрольные точки и байты снимаются согласованно и фиксируются одной транзакцией. PostgreSQL/Redis не нужны для установки, формат существующих данных сохраняется. Встроенная SQLite обновлена до 3.51.3; нативная сборка требует Go 1.25+.

Учёт и квоты работают в памяти при передаче блоков; SQLite не вызывается в пути передачи. Изменившиеся счётчики всех серверов сохраняются одной транзакцией раз в **5 секунд**, HTTP-статистика — раз в 10 секунд. Скорость рассчитывается независимо каждую секунду. Интервал сохранения задаётся через `PANEL_FLUSH_INTERVAL=10s` в `.env` (от `1s` до `1m`); затем пересоздайте панель: `docker compose -p fluxgate up -d --no-deps panel`.

Серверы упорядочены по ID. Опросы интерфейса не накладываются друг на друга. HAProxy использует один master для reload; изменение имени не вызывает reload, квоты/скорость в relay тоже не требуют reload. Direct-фильтры скорости и включение/снятие квоты меняют конфигурацию. Лимит файловых дескрипторов контейнеров/systemd — 1048576, размер Docker-логов ограничен.

В режиме relay каждый клиент занимает два соединения внутри HAProxy, поэтому внешний вход ограничен отдельно (`PANEL_MAX_CONNECTIONS=10000`), а внутреннему TLS-входу зарезервированы места. Это предотвращает взаимную блокировку при заполнении общего лимита, когда CPU свободен, но TLS не отвечает. Клиенты без ClientHello закрываются через 5 секунд; бездействие клиента на внутреннем TLS/HTTP-входе ограничено 30 секундами. Для открытого WebSocket сохраняется таймаут бездействия 1 час.

Буферы Go занимают 32 КиБ на туннель вместо 128 КиБ. Графики кэшируются на 30 секунд, тяжёлые запросы отменяются при отключении клиента и ограничены 10 секундами. CSV и backup сначала готовятся в закрытых временных файлах и только потом отправляются: медленный получатель не удерживает соединение SQLite или блокировку учёта. Старше 90 дней история удаляется небольшими пакетами; текущие счётчики и платежи не очищаются.

Проверка готовности требует реального TLS/HTTP-ответа fallback через 443, а не только открытого TCP listener. При трёх последовательных неудачах сохраняются приватные `incident-latest.json` и `incident-goroutines.txt` в томе данных, не чаще раза в 10 минут. Автоматического слепого рестарта при заполненном лимите нет. В интерфейсе видны текущие/пиковые соединения текущего worker и предупреждение от 80% лимита. `PANEL_MAX_CONNECTIONS` допускает **1–100000** в обоих режимах, по умолчанию 10000; повышение требует запаса RAM/FD и не исправляет утечки.

Если проблема повторится, **до перезапуска** соберите разовый отчёт (совместим и с прежней версией, не меняет данные и не печатает токены):

```bash
curl -fsSL https://raw.githubusercontent.com/bekjonbegmatov/FluxGate/main/deploy/diagnose.py -o /tmp/fluxgate-diagnose.py && sudo python3 /tmp/fluxgate-diagnose.py
```

[Разбор причин деградации и воспроизводимые проверки](docs/PERFORMANCE.md). Без метрик работающего сервера нельзя установить, какой из дефектов проявился именно на нём.

Для гигабитного канала оставьте ограничения скорости равными `0` либо задайте нужные Мбит/с. Итог зависит от CPU/TLS, порта VPS и upstream. Проверка полного HTTPS-пути: `python3 deploy/test-integration.py --seconds 60` на отдельной машине с Docker (тестовые порты 19389/19443). Она проверяет квоты, общий limiter, WebSocket при reload и сохранение счётчиков при рестарте, затем измеряет скорость несколькими окнами. Результат локального теста не гарантирует такую же скорость на другом VPS.

## Запуск на этом VPS (systemd)

Запустите `sudo bash deploy/install-native.sh`. Скрипт собирает Go и веб-интерфейс, создаёт две службы `fluxgate-panel` и `fluxgate-haproxy` и сохраняет случайные секреты в `/etc/fluxgate/fluxgate.env`. Данные находятся в `/var/lib/fluxgate`.

Панель слушает `0.0.0.0:9389` и доступна по HTTP на `http://<IP-сервера>:9389/admin/`. Для локального доступа подходит `http://127.0.0.1:9389/admin/`. При публичном HTTP токен и сессия передаются без шифрования, поэтому используйте доверенную сеть или SSH-туннель для работы с чувствительными данными. Токен для входа смотрите командой `sudo sed -n 's/^PANEL_TOKEN=//p' /etc/fluxgate/fluxgate.env`.

Основной домен этого развёртывания — `cubeland.top`; его можно изменить в разделе «Настройки». Новое значение сохраняется в SQLite и имеет приоритет над `PANEL_DOMAIN`. При необходимости измените `PANEL_TIMEZONE=UTC` в `/etc/fluxgate/fluxgate.env`, затем выполните `sudo systemctl restart fluxgate-panel`. Направьте основной домен и SNI-имена серверов на VPS. Для `*.api.example.com` нужна wildcard-запись DNS.

## Запуск через Docker Compose

Скопируйте `.env.example` в `.env`, задайте домен и два разных длинных секрета, затем выполните `docker compose up -d --build`. Порт 9389 публикуется на всех интерфейсах хоста.

Публичный HAProxy слушает 443 с самоподписанными сертификатами. Клиенту понадобится доверять им или принять предупреждение. Для неизвестного SNI используется сертификат основного домена, поэтому браузер обычно покажет ошибку имени до fallback-страницы.

## Как работает трафик

Ниже описан режим **relay**. В режиме **direct** TLS завершается сразу на публичном frontend HAProxy, который обращается к upstream без Go и внутреннего второго frontend.

**Почему у хостера может быть почти ×2.** Панель считает клиентскую сторону маршрутов, а не весь порт сервера. При скачивании 1 GiB прокси получает примерно 1 GiB от upstream и отправляет примерно 1 GiB клиенту. Если провайдер суммирует RX+TX, он покажет около 2 GiB, плюс накладные расходы и другой трафик. Это условное объяснение, не утверждение о конкретном тарифе провайдера. Сравнивайте одинаковые периоды; «за всё время» панели и «за месяц» хостера не совпадают автоматически. UI использует KiB/MiB/GiB/TiB (1024), а не KB/MB/GB/TB (1000); 1 TiB ≈ 1,10 TB. Счётчики клиентов не умножаются на два.

В CPU-карточке показана работа процессоров **без iowait и steal**, отдельно доступны ожидание диска, softirq и steal, число логических CPU. Softirq входит в загрузку CPU; это не дополнительный процент. Прежний показатель уже исключал iowait, но не показывал его отдельно, включал steal и дважды суммировал guest CPU. Высокую старую загрузку нельзя объяснять только ожиданием I/O. Метрики относятся ко всему хосту, не только FluxGate; по ним нельзя определить виновный процесс.

HAProxy читает SNI из TLS ClientHello на 443 и выбирает маршрут. К Go relay он подключается по приватному Unix-сокету маршрута, без расходования TCP-портов. Go считает TLS-байты и ограничивает общую скорость/квоты, затем выбирает наименее занятый из 16 внутренних TLS-входов HAProxy на loopback 8443–8458 (равные варианты выбираются по кругу). Это распределяет TCP tuple pools и сохраняет TCP RST для гарантированного закрытия внутреннего WebSocket при отмене. TLS завершается там, а HTTP/WS направляются к конечному HTTP/HTTPS-серверу. Основной домен и неизвестные имена показывают fallback. Внутренние порты не публикуются.

Для квоты выбирается приём, отдача или оба направления. Считаются успешно записанные в сокет байты TLS-потока, включая TLS-заголовки и рукопожатие, без TCP/IP-заголовков и повторных передач. Счётчики сохраняются каждые 5 секунд и принудительно при штатном завершении и backup. При аварии могут потеряться данные после последнего успешного сохранения (обычно до 5 секунд; при отказе диска — больше). После достижения лимита новые HTTP-запросы получают 429, а активные соединения закрываются. Пауза даёт 503. День начинается в 00:00 `PANEL_TIMEZONE`. Месячный период начинается в число создания сервера; если такого числа в месяце нет, используется последний день.

Папка `/var/lib/fluxgate` или Docker-том содержит SQLite, сертификаты и конфигурацию HAProxy. Для резервной копии используйте ZIP из панели. Он содержит Telegram bot token в открытом виде, поэтому храните его как секрет. В работающей установке токен Telegram шифруется ключом `PANEL_MASTER_KEY`; смена ключа без восстановления через ZIP делает сохранённый токен недоступным и завершает текущие сеансы панели.

## Проверки разработчика

Из корня проекта: `go test ./...` и `go vet ./...`. В `web/`: `npm ci && npm run build`. При наличии HAProxy приложение проверяет каждую новую конфигурацию командой `haproxy -c`; контейнер HAProxy повторно проверяет её перед перезагрузкой. Щадящая проверка на ноутбуке: `GOMAXPROCS=2 go test -race -p 1 ./...`, затем `COMPOSE_PARALLEL_LIMIT=1 python3 deploy/test-integration.py --functional-only`. Последняя пропускает throughput/большую историю, проверяет протоколы на малом числе соединений и ограничивает CPU тестовых контейнеров; она не доказывает ёмкость 100k. Go-сборки Docker ограничены двумя CPU по умолчанию (`GO_BUILD_PROCS`), тестовый сценарий использует один.

## Разделы и аренда

У разделов отдельные адреса: `/admin/` — обзор, `/admin/servers` — серверы, `/admin/servers/ID` — сервер, `/admin/finance` — финансы, `/admin/finance/ID` — аренда, `/admin/settings` — настройки. График трафика показывает суммарные данные или данные выбранного сервера за 1 час, 24 часа, 7, 30 или 90 дней. Наведите курсор для значений по интервалу; легенда включает и выключает направления.

В аренде администратор сохраняет арендатора и контакт. Каждая оплата записывается с суммой и новой датой «оплачено до»: например, $10 до 10 числа, затем следующая оплата до 17 числа. Панель показывает общую полученную сумму и историю продлений. Если включено напоминание, в день окончания оплаченного срока панель отправит одно сообщение Telegram после 09:00 в `PANEL_TIMEZONE` о необходимости продления. Дополнительная TCP-проверка конечного сервера включается отдельно для каждого маршрута; уведомление об отказе отправляется после пяти минут непрерывной недоступности, затем при восстановлении.

Для настройки swap на VPS: `sudo bash deploy/setup-swap.sh`. Скрипт идемпотентно создаёт swapfile 2 ГБ и устанавливает `vm.swappiness=10` с сохранением после перезагрузки. На текущем VPS это уже выполнено.

## Статистика запросов и экспорт

Панель считывает из HAProxy запросы, ответы 2xx/3xx/4xx/5xx, активные соединения и среднее время ответа backend. История собирается каждые 10 секунд с момента включения функции и хранится 90 дней. На страницах сервера и обзора доступны графики ошибок и запросов. Экспорт трафика (по дням или часам) и оплат доступен только после входа; в CSV можно выбрать период и сервер. Трафик в CSV сгруппирован по UTC.

## Резервная копия через панель

В «Настройках» можно скачать ZIP с согласованной копией SQLite, сертификатами и настройками. Там же архив загружается для восстановления на этой или новой установке; сервис проверяет файл и перезапускается. Токен для входа остаётся токеном целевой установки. Архив содержит Telegram bot token в открытом виде — обращайтесь с ним как с секретом. [Подробности и ручной откат](docs/OPERATIONS.md#backup-и-восстановление).
