# Fluxgate — панель управления HAProxy

Панель для маршрутизации по TLS SNI, учёта трафика серверов, квот и общих ограничений скорости. Поддерживает HTTP/1.1 и WebSocket.

## Установка одной командой на чистый Ubuntu/Debian

```bash
curl -fsSL https://raw.githubusercontent.com/bekjonbegmatov/FluxGate/main/install.sh -o /tmp/fluxgate-install.sh && sudo bash /tmp/fluxgate-install.sh
```

Скрипт установит Docker Engine и Compose, скачает проект, создаст случайные секреты, запустит контейнеры и напечатает готовый HTTP URL и токен входа. По умолчанию основной домен `cubeland.top`; для другого домена задайте `sudo FLUXGATE_DOMAIN=example.com bash /tmp/fluxgate-install.sh`. Откройте TCP 443 и 9389 в firewall хостинга. Повторный запуск сохраняет секреты и данные. [Подробная эксплуатация](docs/OPERATIONS.md).

## Обновление работающей Docker-установки одной командой

```bash
curl -fsSL https://raw.githubusercontent.com/bekjonbegmatov/FluxGate/main/update.sh -o /tmp/fluxgate-update.sh && sudo bash /tmp/fluxgate-update.sh
```

Обновлятор собирает новые образы при работающем прокси, скачивает и проверяет backup, сохраняет `.env` и прежние образы в `/var/backups/fluxgate/<дата>`. После переключения проверяет готовность, вход в API и полный TLS/SNI-путь через 443. При неудаче возвращает прежние образы с тем же томом данных. Во время переключения будет короткий перерыв: текущим соединениям потребуется переподключиться. Код обновляется только fast-forward; локальные изменения не перезаписываются.

По умолчанию checkout находится в `/opt/fluxgate`, Compose-проект — `fluxgate`. Для другой папки: `sudo FLUXGATE_DIR=/ваша/папка bash /tmp/fluxgate-update.sh`. Домены, маршруты, токены, сертификаты и платежи сохраняются. При нестандартных Compose override-файлах используйте ручное обновление из [инструкции эксплуатации](docs/OPERATIONS.md).

## Производительность и длительная работа

Учёт и квоты работают в памяти при передаче блоков; SQLite не вызывается в пути передачи. Изменившиеся счётчики всех серверов сохраняются одной транзакцией раз в **5 секунд**, HTTP-статистика — раз в 10 секунд. Скорость рассчитывается независимо каждую секунду. Интервал сохранения задаётся через `PANEL_FLUSH_INTERVAL=10s` в `.env` (от `1s` до `1m`); затем пересоздайте панель: `docker compose -p fluxgate up -d --no-deps panel`.

Серверы упорядочены по ID. Опросы интерфейса не накладываются друг на друга. HAProxy использует один master для reload; изменение имени, квоты или скорости не вызывает reload. Лимит файловых дескрипторов — 262144, размер Docker-логов ограничен.

Каждый клиент занимает два соединения внутри HAProxy, поэтому внешний вход ограничен отдельно (`PANEL_MAX_CONNECTIONS=10000`), а внутреннему TLS-входу зарезервированы места. Это предотвращает взаимную блокировку при заполнении общего лимита, когда CPU свободен, но TLS не отвечает. Клиенты без ClientHello закрываются через 5 секунд; бездействие клиента на внутреннем TLS/HTTP-входе ограничено 30 секундами. Для открытого WebSocket сохраняется таймаут бездействия 1 час.

Буферы Go занимают 32 КиБ на туннель вместо 128 КиБ. Графики кэшируются на 30 секунд, тяжёлые запросы отменяются при отключении клиента и ограничены 10 секундами. CSV и backup сначала готовятся в закрытых временных файлах и только потом отправляются: медленный получатель не удерживает соединение SQLite или блокировку учёта. Старше 90 дней история удаляется небольшими пакетами; текущие счётчики и платежи не очищаются.

Если проблема повторится, **до перезапуска** соберите разовый отчёт (совместим и с прежней версией, не меняет данные и не печатает токены):

```bash
curl -fsSL https://raw.githubusercontent.com/bekjonbegmatov/FluxGate/main/deploy/diagnose.py -o /tmp/fluxgate-diagnose.py && sudo python3 /tmp/fluxgate-diagnose.py
```

[Разбор причин деградации и воспроизводимые проверки](docs/PERFORMANCE.md). Без метрик работающего сервера нельзя установить, какой из дефектов проявился именно на нём.

Для гигабитного канала оставьте ограничения скорости равными `0` либо задайте нужные Мбит/с. Итог зависит от CPU/TLS, порта VPS и upstream. Проверка полного HTTPS-пути: `python3 deploy/test-integration.py --seconds 60` на отдельной машине с Docker (тестовые порты 19389/19443). Она проверяет квоты, общий limiter, WebSocket при reload и сохранение счётчиков при рестарте, затем измеряет скорость несколькими окнами. Результат локального теста не гарантирует такую же скорость на другом VPS.

## Запуск на этом VPS (systemd)

Запустите `sudo bash deploy/install-native.sh`. Скрипт собирает Go и веб-интерфейс, создаёт две службы `fluxgate-panel` и `fluxgate-haproxy` и сохраняет случайные секреты в `/etc/fluxgate/fluxgate.env`. Данные находятся в `/var/lib/fluxgate`.

Панель слушает `0.0.0.0:9389` и доступна по HTTP на `http://<IP-сервера>:9389/admin/`. Для локального доступа подходит `http://127.0.0.1:9389/admin/`. При публичном HTTP токен и сессия передаются без шифрования, поэтому используйте доверенную сеть или SSH-туннель для работы с чувствительными данными. Токен для входа смотрите командой `sudo sed -n 's/^PANEL_TOKEN=//p' /etc/fluxgate/fluxgate.env`.

Основной домен этого развёртывания — `cubeland.top`; его можно изменить в разделе «Настройки». Новое значение сохраняется в SQLite и имеет приоритет над `PANEL_DOMAIN`. При необходимости измените `PANEL_TIMEZONE=UTC` в `/etc/fluxgate/fluxgate.env`, затем выполните `sudo systemctl restart fluxgate-panel`. Направьте основной домен и SNI-имена серверов на VPS. Для `*.api.example.com` нужна wildcard-запись DNS.

## Запуск через Docker Compose

Скопируйте `.env.example` в `.env`, задайте домен и два разных длинных секрета, затем выполните `docker compose up -d --build`. Порт 9389 публикуется на всех интерфейсах хоста.

Публичный HAProxy слушает 443 с самоподписанными сертификатами. Клиенту понадобится доверять им или принять предупреждение. Для неизвестного SNI используется сертификат основного домена, поэтому браузер обычно покажет ошибку имени до fallback-страницы.

## Как работает трафик

HAProxy читает SNI из TLS ClientHello на 443 и выбирает маршрут. Локальный сервис Go считает байты TLS-потока и ограничивает общую скорость для всех соединений сервера. Затем поток возвращается в HAProxy на внутренний порт 8443: там завершается TLS, а HTTP или WebSocket направляются к конечному HTTP/HTTPS-серверу. Основной домен всегда показывает редактируемую fallback-страницу; неизвестные имена тоже направляются на неё.

Для квоты выбирается приём, отдача или оба направления. Считаются успешно записанные в сокет байты TLS-потока, включая TLS-заголовки и рукопожатие, без TCP/IP-заголовков и повторных передач. Счётчики сохраняются каждые 5 секунд и принудительно при штатном завершении и backup. При аварии могут потеряться данные после последнего успешного сохранения (обычно до 5 секунд; при отказе диска — больше). После достижения лимита новые HTTP-запросы получают 429, а активные соединения закрываются. Пауза даёт 503. День начинается в 00:00 `PANEL_TIMEZONE`. Месячный период начинается в число создания сервера; если такого числа в месяце нет, используется последний день.

Папка `/var/lib/fluxgate` или Docker-том содержит SQLite, сертификаты и конфигурацию HAProxy. Для резервной копии используйте ZIP из панели. Он содержит Telegram bot token в открытом виде, поэтому храните его как секрет. В работающей установке токен Telegram шифруется ключом `PANEL_MASTER_KEY`; смена ключа без восстановления через ZIP делает сохранённый токен недоступным и завершает текущие сеансы панели.

## Проверки разработчика

Из корня проекта: `go test ./...` и `go vet ./...`. В `web/`: `npm ci && npm run build`. При наличии HAProxy приложение проверяет каждую новую конфигурацию командой `haproxy -c`; контейнер HAProxy повторно проверяет её перед перезагрузкой.

## Разделы и аренда

У разделов отдельные адреса: `/admin/` — обзор, `/admin/servers` — серверы, `/admin/servers/ID` — сервер, `/admin/finance` — финансы, `/admin/finance/ID` — аренда, `/admin/settings` — настройки. График трафика показывает суммарные данные или данные выбранного сервера за 1 час, 24 часа, 7, 30 или 90 дней. Наведите курсор для значений по интервалу; легенда включает и выключает направления.

В аренде администратор сохраняет арендатора и контакт. Каждая оплата записывается с суммой и новой датой «оплачено до»: например, $10 до 10 числа, затем следующая оплата до 17 числа. Панель показывает общую полученную сумму и историю продлений. Если включено напоминание, в день окончания оплаченного срока панель отправит одно сообщение Telegram после 09:00 в `PANEL_TIMEZONE` о необходимости продления. Дополнительная TCP-проверка конечного сервера включается отдельно для каждого маршрута; уведомление об отказе отправляется после пяти минут непрерывной недоступности, затем при восстановлении.

Для настройки swap на VPS: `sudo bash deploy/setup-swap.sh`. Скрипт идемпотентно создаёт swapfile 2 ГБ и устанавливает `vm.swappiness=10` с сохранением после перезагрузки. На текущем VPS это уже выполнено.

## Статистика запросов и экспорт

Панель считывает из HAProxy запросы, ответы 2xx/3xx/4xx/5xx, активные соединения и среднее время ответа backend. История собирается каждые 10 секунд с момента включения функции и хранится 90 дней. На страницах сервера и обзора доступны графики ошибок и запросов. Экспорт трафика (по дням или часам) и оплат доступен только после входа; в CSV можно выбрать период и сервер. Трафик в CSV сгруппирован по UTC.

## Резервная копия через панель

В «Настройках» можно скачать ZIP с согласованной копией SQLite, сертификатами и настройками. Там же архив загружается для восстановления на этой или новой установке; сервис проверяет файл и перезапускается. Токен для входа остаётся токеном целевой установки. Архив содержит Telegram bot token в открытом виде — обращайтесь с ним как с секретом. [Подробности и ручной откат](docs/OPERATIONS.md#backup-и-восстановление).
