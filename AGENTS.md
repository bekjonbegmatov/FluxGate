# FluxGate: инструкции для работающих с репозиторием агентов

Прочитайте [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) и [docs/OPERATIONS.md](docs/OPERATIONS.md) перед изменениями в маршрутизации, базе или развёртывании. README описывает установку и пользовательские сценарии. Эти файлы — актуальное описание проекта; при изменении поведения обновляйте их вместе с кодом.

## Назначение и жёсткие договорённости

- Публичный трафик входит через HAProxy на 443. Админка доступна по **HTTP** на 9389, путь `/admin/`. Текущая установка слушает все интерфейсы. Не меняйте этот пользовательский выбор самовольно.
- Главный домен — fallback. Он редактируется в настройках и хранится в SQLite как `settings.domain`; значение из `PANEL_DOMAIN` используется при первом старте. Нельзя назначить основной домен серверному маршруту.
- SNI маршрутизирует TLS до расшифровки. HTTP и WebSocket проходят через внутренний TLS frontend HAProxy. Ограничение скорости и квоты реализует Go relay, поэтому нельзя обойти его прямым backend HAProxy.
- Самоподписанные сертификаты создаёт Go и хранит в `PANEL_DATA/certs`. Их предупреждение в браузере ожидаемо до установки доверия.
- Финансы — журнал **полученных оплат** и дата «оплачено до». Здесь нет долга или автоматического начисления. Telegram напоминает о продлении в указанную дату после 09:00 по часовому поясу панели.
- Backup ZIP содержит SQLite, сертификаты и Telegram bot token в manifest.json. Он содержит чувствительные данные. Восстановление сохраняет токен входа текущей установки, шифрует Telegram token её мастер-ключом и перезапускает сервис.
- Секреты нельзя добавлять в Git, логи, тестовые фикстуры с реальными значениями или текст ответа. `.env`, `data/*`, `web/dist` игнорируются Git.

## Безопасная последовательность разработки

1. Сначала изучите связанные файлы, активный процесс и состояние Git. Текущие пользовательские данные живут в `/var/lib/fluxgate` в нативной установке либо в томе Compose. Не редактируйте их напрямую ради тестов.
2. Для изменений схемы делайте идемпотентную миграцию и тест на старую базу. SQLite использует WAL и `SetMaxOpenConns(1)`.
3. Для изменений HAProxy прогоняйте `haproxy -c` через `writeConfig`; watcher подхватывает новый конфиг после атомарного rename. Проверяйте 443 после развёртывания.
4. Для API и backup пишите содержательные тесты на временном SQLite. ZIP на восстановление проверяется до установки маркера перезапуска.
5. Выполняйте `go test ./...`, `go vet ./...`, `npm --prefix web run build`, `git diff --check`. При изменениях установщика — `bash -n install.sh`.
6. На нативном VPS соберите `go build -o /usr/local/bin/fluxgate-panel.new ./cmd/panel`, установите бинарник, скопируйте `web/dist`, перезапустите `fluxgate-panel.service`, проверьте обе службы и HTTP API. Для Docker используйте `docker compose -p fluxgate up -d --build`.
7. Делайте небольшие осмысленные коммиты. Обновляйте README и документацию при изменении функций или ограничений.

Для изменений relay/accounting выполняйте также `go test -race ./...`. Не удерживайте `RouteState.mu` во время SQL, сетевых операций или ожидания limiter. `stateMu` сериализует изменения маршрутов и persistence; после DB commit вычитайте только сохранённые дельты. Метаданные маршрута нельзя откатывать вместе с накопленными за время запроса байтами. Новые изменения updater проверяйте `python3 deploy/test-update.py`. Полный TLS/reload/quota/restart-тест — `python3 deploy/test-integration.py --seconds 60` в отдельном локальном Docker-проекте.

## Нетривиальные детали

- `PANEL_SECRET_PATH` на уровне Go настраивается, но собранный Vite использует статическую базу `/admin/`. Установщик фиксирует `admin`. Изменение пути требует также изменения `web/vite.config.ts` и новой сборки.
- `request_totals` начинается с момента включения статистики; счётчики HAProxy на первом опросе берутся как baseline, чтобы после перезапуска не удвоить прошлые запросы. После reload HAProxy уменьшившиеся счётчики считаются с нуля.
- `samples` и `request_samples` очищаются после 90 дней. CSV трафика группирует по UTC; начало и конец фильтра рассчитываются по часовому поясу панели.
- В нативной установке stats socket HAProxy получает группу `fluxgate`; в Docker панель работает root в своём контейнере и использует общий том.
- Восстановление отвечает 202, ставит `restore.pending`, затем процесс завершается. systemd либо Docker restart запускает его снова; до открытия SQLite `applyPendingRestore` меняет базу и сертификаты, сохраняет прежние файлы в `before-restore-*`.
- Из-за публичного HTTP токен, cookie и резервный архив передаются без транспортного шифрования. Не представляйте это в UI как защищённое соединение.
